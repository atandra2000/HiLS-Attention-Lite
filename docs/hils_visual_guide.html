Read this boundary first. The current model is causal between chunks, but its SDPA calls are unmasked inside each selected chunk. Pooled queries and the current landmark also summarize the whole chunk. Earlier positions can therefore depend on later tokens in that chunk. The cached path reproduces this teacher-forced operator; it does not establish token-by-token autoregressive correctness.

Model

Tokens become 1024-wide vectors. Each of 24 pre-normalized blocks adds an attention residual and a SwiGLU residual. The final RMSNorm runs once after the stack; the vocabulary head shares the embedding matrix.

corpus to tensors

Data

The local preparation shim delegates download, cleaning, deduplication, tokenization and packing to workspace shared_data. It writes a local GPT-2 tokenizer configuration: vocabulary 50,257; EOS and padding ID 50,256. The declared eight-billion-token recipe is FineWeb-Edu 40%, DCLM 15%, Python 15%, Jupyter 5%, OpenMath 10%, arXiv 10% and Cosmopedia 5%.

source documents → clean / deduplicate → GPT-2 + EOS → raw uint16 shards (GPT-2 packer selection) 50,000,000 tokens × 2 bytes = 100 MB raw payload per full shard manifest + shards → ShardDataset memmaps → copy all tokens into np.empty(total) 95/5 train-validation split → PackedDataset → RandomSampler → DataLoader

The active loader allocates a flat host array. It does not retain an entirely disk-backed corpus: If 8B tokens are loaded, the uint32 host array alone is 32 GB, while packed uint16 payload is 16 GB. These are calculated payloads, not measured RSS or verified corpus inventory. The packer selects dtype from vocabulary size; the actual manifest remains authoritative. Each sample then copies T+1 tokens and converts input/target to int64. The loader requests four workers, prefetch factor four and pinned memory. Training transfers use ordinary .to(device); pinned storage alone does not prove asynchronous overlap.

window: [A, B, EOS, C, D] input: [A, B, EOS, C] target: [B, EOS, C, D] window stride = T + 1; incomplete tails are dropped

EOS marks a document boundary; PackedDataset does not create a document attention mask or pad each document into its own training window. Consequently “documents never cross windows” is not a consumer guarantee. The phase switch rebuilds the loader at 16K over the same shards. It does not reserve a separate, previously unseen 1B-token corpus. The training loop receives only the training loader and does not evaluate the returned validation loader.

Step counts refer to optimizer updates. Tokens seen count processed positions, including any repeated corpus content; rollback restores that counter. Finite micro-losses are divided by accumulation before backward. Once the accumulation window completes, the loop sets LR, clips gradients to norm 1, applies AdamW, clears gradients and increments the step. Partial accumulation is discarded at loader exhaustion or phase change.

Learning-rate schedule explorer

The first LR is 3e−4 / 2000 = 1.5e−7. Warmup reaches 3e−4 at index 1999. One cosine decays toward 1.5e−5 across both phases. At index 53,407, a 500-update sine tent starts; it reaches the peak LR halfway through and rejoins the cosine at the end.

Recovery and checkpoint guarantees

A nonfinite loss clears all accumulated gradients and resets the micro-step counter. The bad-loss streak resets after a successful optimizer update, so “five consecutive bad micro-batches” is not the exact rule. At threshold five the latest checkpoint is restored; absent or repeatedly ineffective recovery raises an error.

The selection watchdog checks the worst layer’s max-share after updates. A share above 0.5 for 500 consecutive optimizer updates triggers rollback or failure. Periodic saving occurs before this watchdog check, so “last good” is not an independently validated designation.

Weights, optimizer and JSON metadata are written directly to three files. Completeness checks only file existence. These are not atomic checkpoint sets; RNG, sampler progress and data cursor are not restored. CPU resume tests demonstrate their controlled test case, not arbitrary interrupted-run replay.

Distinctive mechanism

interactive routing laboratory

Shared choices. Different weights for each head.

First form q̄ᵢ = mean(Qᵢ) and ℓⱼ = Wℓ mean(Kⱼ). Score each pair with sᵢⱼₕ = q̄ᵢₕ · ℓⱼ,kv(h) / √64. Selection ranks the mean score across heads; tied scores prefer the more recent chunk. Slot zero always contains the current chunk. Up to seven earlier chunks fill the remaining slots.

Softmax runs on each head’s selected scores. Unavailable early-prefix slots repeat the own index but carry −∞ scores, so they receive zero weight. Each selected chunk gets its own token-level SDPA softmax; fusion then combines those chunk outputs. One softmax over all k×C keys would be a different operator.

oᵢₕ = Σⱼ∈selected(i) softmaxⱼ(sᵢⱼₕ) × SDPA(Qᵢₕ, Kⱼ, Vⱼ) Selection indices: discrete; no straight-through selection in the default config. Selected scores: differentiable through fusion into Q and landmark parameters. Auxiliary term: 0.01 × N × Σⱼ pⱼ², using soft fusion mass; averaged over layers.

Illustrative scores, four query heads. Change the displayed head: membership stays fixed while the orange weight bars change. “Equal scores” demonstrates the recent-chunk tie rule.

Balance encourages distributed use; it cannot guarantee that collapse never occurs. The hard-count watchdog is separate: it deduplicates padded selections and monitors max-share.

cached chunk evaluation

Sparse reads do not imply a sparse cache.

HiLSCache stores all K/V chunks and their landmarks per layer. Prefill calls the same chunk step repeatedly. Each step requires all 128 input tokens of the next chunk, projects and rotates them, stores their K/V and landmark, routes against the prefix, gathers selected chunks and returns 128-position logits.

one complete input chunk → cache its K/V + landmark → score prefix landmarks → own + top-(k−1) earlier chunks → per-chunk SDPA → fusion → residual / FFN → repeat per layer → final norm / head → [B,128,50257] logits

At a 16K prefix, the simple key-read fraction is 1024/16384 = 6.25%. Counting 128 landmark vectors adds 128/(2×16384) = 0.390625%, giving 6.640625% for that single full-prefix step. The repository counter aggregates steps and divides by the final cached length; this is not a profiler measurement of total device traffic.

What the parity tests prove. Cached chunk execution agrees with the full teacher-forced implementation. Both see the complete current chunk. A local one-layer FP64 probe changed token 3 while keeping token 0 fixed and changed token-0 logits by about 0.0614. This demonstrates the within-chunk future dependency. Valid token-autoregressive quality or generation claims require a separate causal design and evaluation review.
